# ROG RTX 3080M UEFI Unlock

Experimental **SS0-only** Tensor Core throughput unlock before Windows boots. Verified on one ASUS ROG Strix G533QS with RTX 3080 Laptop 16GB (GA104M).

[中文说明](README.zh-CN.md) · [Validation](docs/validation/README.md) · [Tests](TESTING.md)

## Measured result

| Dense 8192×8192 GEMM | Saved baseline | After | Change |
|---|---:|---:|---:|
| FP32 | 14.84 TFLOPS | 14.82 TFLOPS | -0.1% |
| TF32 | 22.73 TFLOPS | 22.74 TFLOPS | +0.04% |
| FP16 | 45.32 TFLOPS | 74.65 TFLOPS | **+64.7%** |
| BF16 | 45.20 TFLOPS | 73.03 TFLOPS | **+61.6%** |

Same saved benchmark script, 20-iteration median. Current environment: NVIDIA 621.01, PyTorch 2.8.0+cu128. The earlier handoff recorded PyTorch 2.6.0+cu124; the baseline output has no environment metadata. This is a comparison to a saved baseline, **not a controlled same-environment A/B study**. Six numerical spot checks passed. Long-term stability, sleep/resume, games and application-level acceleration were not validated.

## Behavior and scope

Verifies the board, full PROM hash, assets and cold state; requires a validated independent display GPU and an unbound NVIDIA target; obtains exclusive PCI access; writes `SS0=0x88888888`; preserves SS1; completes one FLR; checks cleanup; starts the existing Windows Boot Manager in the **same boot**.

This port avoids the desktop full-GOP teardown assumption: the independent display remains attached. A physical **U** confirmation is always required. Esc or 30 seconds without confirmation cancels. Cancellation does **not** automatically start Windows.

No VBIOS flashing, power-limit increase or permanent GPU change. Apply again on subsequent boots as needed. A successful board does not establish support for every RTX 30 laptop.

Tested: ASUS G533QS, Ryzen 7 5800H, `10de:249c`, subsystem `1043:1602`, chip `0xb74000a1`, 16GB. Separate AMD GPU owns the physical UEFI GOP. Successful run retained SS1=6, performed one FLR and left no DMA maps.

## Build

Install Bun and LLVM (`clang`, `lld-link`). EDK2 headers are included.

```powershell
bun install --frozen-lockfile
# Only if LLVM is not already on PATH:
$env:LLVM_BIN = 'C:\Program Files\LLVM\bin'
bun run build
```

Output: `build/efi/BOOTX64.EFI`. Build checks AMD64 EFI format and zero imports. Verified v22 SHA256:

```text
b2acc47cf4bd9ca7f5226d0f41003cac272a03ec0fba7b800ba21fee48849911
```

## Dedicated USB workflow

Use a dedicated FAT32 USB and the firmware's one-time boot menu. Keep normal Windows Boot Manager. **Do not overwrite the Windows EFI partition.** This unsigned experimental EFI requires Secure Boot to be disabled on the test machine.

1. Extract the USB ZIP to the USB root. Source builders can run `python tools/package_release.py` after building.
2. Run `Fetch-Firmware.cmd` (Bun required) to generate the pinned firmware locally into `RTX-UNLOCK/ASSETS`. NVIDIA binaries are not shipped in the public package.
3. Keep `RTX-UNLOCK/DEBUG.ON`. Do not copy another machine's `PROFILE.BIN` or PROM; a local profile is generated by the application.
4. Boot the USB. Read preflight results, then press **U once**. The verified machine took about 25 seconds from confirmation to Windows. Do not retry within the same boot.
5. Once Windows starts, run `python benchmarks/gemm_bench.py 8192` and inspect USB `RTX-UNLOCK/RUNxx` logs. A blank or static screen is not proof of success.

If preflight refuses, preserve logs and return to normal Windows boot. If execution reports uncertain cleanup/STOP or hangs, power off before returning to normal boot. GPU initialization/reset errors can leave it hung; recovery and compatibility are not universal.
